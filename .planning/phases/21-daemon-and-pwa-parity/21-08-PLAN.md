## What this client reads (owned by 21-01, 21-02, 21-03, 21-04; restated, not redefined)

- `POST /removals/preview`, body `RemovalTarget` JSON, 200 `RemovalReport` with `planned: true`.
- `POST /removals`, body the previewed `RemovalReport` JSON verbatim. 200 `RemovalReport`; 409 a
  fresh `RemovalReport`, the only JSON error body, nothing removed; every other error body is plain
  text. The authoritative table is `21-03-PLAN.md:90-108`: 404 the target row does not exist, read
  as "already gone", drop and close; 500 a runtime survived; 503 persistence failure, missing
  runtime handle, blocked daemon or `repository busy:`, and a blocked daemon answers 503 before
  404. 500 and 503 are retryable; 404 is not.
- `GET /rows`, the 21-02 pinned list: top level `repositories` and `standalone`; repository entry
  `repository_key`, `display_name`, `path`, `health`, `checkouts`; checkout entry `checkout_key`,
  `repository_key`, `display_name`, `branch`, `path`, `role`, `managed_by_baude`, `archived`,
  `session_id`; standalone entry `standalone_key`, `display_name`, `path`, `archived`,
  `session_id`. Keys are bare `u64` on the wire.
- `GET /events`, `text/event-stream`, named event `rows_removed`, one `data:` line holding a
  `RemovalReport`; comment frames from `KeepAlive::default()`; no `id:`, no replay, silent skip on
  lag, no ordering against the POST response. A missed event converges only through the `/rows` poll.
- `/sessions` carries no `checkout_key` (D-09 option B). The join is `session_id`.
</wire_contract>
