<objective>
The pure, dependency-free seam the PWA removal work stands on. `bauded/web/removal.js` holds
every transform that can be stated as a function of its arguments — report to confirmation view,
view to HTML, key to name, snapshot to arbitrated snapshot — and `bauded/web/tests/removal.test.js`
covers them under `node --test` with no package, no browser and no build step.

This plan exists because both review lanes closed on the same defect in the old 21-05: its
headline XSS mitigation had no automated evidence, because `confirmationView` returned plain data
and a test over plain data can only assert that the view model *preserves* an angle bracket — the
opposite of the property at risk. Moving the `innerHTML` interpolation into
**`renderConfirmation(view) → html`** makes the escaping claim a string assertion over the exact
layer that writes to the DOM. Two client HIGHs (#5 pending-refresh resurrection, #6 report keys
with no child names) also have pure halves that were previously buried inside browser wiring;
they land here as `applySnapshot`/`tombstone` and `rowsIndex`/`reportRowNames`, where they can be
tested rather than hoped for.

Purpose: give 21-05 a controller plan with nothing left to prove except wiring.
Output: one module, one Node suite, zero dependencies, no file outside `bauded/web/` touched.

**Scope fence.** This plan does not register the asset, does not touch `bauded/web/app.js`,
`index.html`, `sw.js`, `style.css` or `bauded/src/web.rs`, and does not add a route. Asset
registration and the `.box.wide` CSS are 21-05's (and `removal.js` existing first is why
`include_bytes!` cannot break there). The repository gates over the final tree are 21-11's.
</objective>
