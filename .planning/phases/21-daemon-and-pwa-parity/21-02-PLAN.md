## `GET /rows` — the pinned field list

This is the wire contract. 21-05 (`bauded/web/app.js`), 21-07 (`bauded/web/removal.js` fixtures; that file is new in 21-07 and absent from the tree today) and
21-08 (`baude/src/remote.rs` deserialize) all read it. **Field names are fixed here.** A change
after this plan lands means touching three callers, which is why the task carries
`reversibility rating="costly"`.

Top level — one JSON object, two arrays, never a bare array (so a future third root kind is
additive rather than breaking):

- `repositories` — array of repository parent entries, in `first_seen_order`
- `standalone` — array of standalone root entries, in `first_seen_order`

Repository parent entry fields:

- `repository_key` — bare `u64` (the `RepositoryKey` newtype is serde-transparent; confirm at `baude-core/src/repository.rs:8-13` before writing fixtures)
- `display_name` — the file name of `observed_main_worktree`
- `path` — `observed_main_worktree` as a display string, absolute, not tilde-shortened (`tildePath()` is client-side, 21-07)
- `health` — the existing `RepositoryHealth` serde form, verbatim
- `checkouts` — array of checkout child entries, in `first_seen_order`

Checkout child entry fields:

- `checkout_key` — bare `u64`
- `repository_key` — bare `u64`, the parent key repeated so a flattened client list can still find its parent
- `display_name` — `SavedCheckout.session.name`
- `branch` — `observed_branch`, **verbatim and unnormalized** (`Option<String>`; may read `refs/heads/topic`). Normalization and the main-checkout role correction are **21-09's scope**, not this plan's: the field name is fixed here, its value correctness is fixed there
- `path` — `observed_path` as a display string
- `role` — the existing `CheckoutRole` serde form (`main` / `primary_default` / `managed_branch`), verbatim
- `managed_by_baude` — `bool`
- `archived` — `SavedCheckout.session.archived`
- `session_id` — `Option<u64>`, the live daemon session id from `runtime_checkouts`, `null` when the row has no live runtime

Standalone root entry fields:

- `standalone_key` — bare `u64`
- `display_name` — `SavedStandaloneSession.session.name`
- `path` — `canonical_path` as a display string
- `archived` — `session.archived`
- `session_id` — `Option<u64>`, **always `null` until 21-10** adds a daemon standalone runtime registry. The field is present and honestly null; it is not omitted and it does not imply coverage

**Not on this projection, deliberately:** `resume_id` / `claude_session_id` or any other conversation
identifier (prohibition 2), `owned_runtime` internals, and `lifecycle`. `/rows` is a naming and keying
index; the per-session detail surface is `/sessions` and `/sessions/{id}`.
</wire_contract>
