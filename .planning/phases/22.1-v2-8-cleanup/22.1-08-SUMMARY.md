# Phase 22.1 Plan 08: core removal stages and redirect carrier Summary

Core removal now runs as three public stages, `prepare`, `stop_and_delete` and `commit`, and `remove` is their composition with the same signature and behaviour. `commit` rebuilds the save candidate from the state it is handed. It also refuses with `SelectionChanged` when the target no longer selects the prepared rows. A test can now carry its fixture redirects to another thread with `capture` and `TestRedirect::install`. Every red was shown failing for its named reason before its fix.

## What was built

- **`prepare(&state, target, &[RowRuntime])`** runs `select_rows`, `planned_clearings`, `preflight`, then `candidate_without`, which builds the candidate, validates it and throws it away. It touches no runtime, disk or file. `PreparedRemoval` holds only the set and the planned clearings.
- **`stop_and_delete(&prepared, &mut [RowRuntime])`** runs `kill_stage` then `disk_stage` and reads no `RepositoryState`. It returns `StageEffects`, which holds the killed runtimes and the disk results.
- **`commit(&mut state, prepared, effects, &mut Vec<RowRuntime>, save)`**:
  1. `reselect` compares the prepared row keys with `select_rows(*state, target)` as sets. On any difference it returns `SelectionChanged`. A target that no longer resolves counts as found empty.
  2. `candidate_without(*state)` builds the candidate and validates it.
  3. `persist_stage` saves once, then `clear_stage` runs with the rows the clone dropped, then `report_from_set`.
  
  `*state` is untouched on every error.
- **`RemovalError::SelectionChanged { target, expected, found }`** has a Display that names both lists and says nothing was saved. It has no `source`.
- **`remove`** is `prepare`, then `stop_and_delete`, then `commit`. Its doc comment keeps the whole contract text and gains one paragraph. That paragraph names the three stages and says a caller running them apart must hold an exclusion across the window.
- **bauded `removal_error`** maps `SelectionChanged` to 500 in the existing arm. A comment says it follows a kill and a delete and is unreachable under the daemon's exclusion.
- **`testing::capture()`** returns the calling thread's `Redirects`. **`TestRedirect::install(redirects)`** swaps them in through `swap` and restores on drop. Both doc comments say that redirects are thread-local and must be captured on one thread and installed on the other. A `const` assertion keeps `Redirects: Send`.

## Deviations from Plan

1. **[Rule 3] The SelectionChanged RED test could not name the variant.** A test that matched `RemovalError::SelectionChanged` would not compile before the fix, so it could not fail for the named reason. A test that only checked "Err, state untouched, no save" would already have passed, because commit returned `Validation`. The test therefore identifies the refusal by:
   - its Debug name starting with `SelectionChanged`
   - a Display containing both `{expected:?}` and `{found:?}`, the prepared keys and a fresh `select_rows`; the daemon sends that Display as the 500 body
   - `source()` being `None`

   It is unchanged between c460ebb and e5c393f.
2. **[Rule 1] Clippy `type_complexity` on the new test helper.** `recording_save` returned `(impl FnOnce, Rc<RefCell<Option<RepositoryState>>>, Rc<Cell<u32>>)`. bd83686 folds the count and the received state into one `SaveRecord`. The test still asserts one call and the same received-state checks. This was not caught before Task 2's verify, because Task 1's verify does not run clippy.
3. **fmt amend of the first RED commit.** e96f3a9 was committed with unformatted lines because `fmt --check` and `git commit` were joined with `;`. It was amended in place to c1e69db before anything else happened, and nothing was pushed. Its RED was rerun on c1e69db.
4. **Logs:** Task 2's verify sends clippy output to `target/gsd-22.1/08-clippy.log` in place of the terminal. Its exit is still captured on its own statement.
5. **Two additions beyond the listed shapes:**
   - a private `candidate_without` helper, shared by `prepare` and `commit`
   - a private `reselect`

   Neither is public. A `PreparedRemoval::set()` accessor was drafted and dropped before the refactor commit, since plan 22.1-10 does not use one.
