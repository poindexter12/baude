# Phase 22.1 Plan 04: baude-core fixture roots on FixtureRoot Summary

All 21 `std::env::temp_dir()` fixture sites in the fourteen listed `baude-core` files now build their root through `FixtureRoot`. The whole `baude-core` lib suite, 581 tests, runs under `scripts/assert-no-test-leftovers.sh` with `command=0 orphans=0 live=0 dirs=0`. The before-runs left 14, 15 and 41 fixture roots.

## What was built

- **Helpers returning a root now return a `FixtureRoot`:**
  - `hook::seed_guard_cwd` and `backend::claude::mcp_guard_cwd`
  - `backend::claude::resume_fixture`, which returns `(FixtureRoot, TestRedirect)`
  - `meta::isolated_claude_root`, `persist::isolated_root` and `marker::test_dir`
  - the `scratch` helpers in `suppression`, `folder_workspace`, `breadcrumbs` and `launch`
- **Inline roots became `FixtureRoot::new`:**
  - hook `baude-seed-test`, claude `baude-core-mcp-test`, meta `baude-meta-gate-same-tick`
  - git `baude-git-stale-gitfile`, workspace `baude-seeded-cache`
- **File fixture:** meta's `feed_transcript` writes its transcript inside a `FixtureRoot` and returns `(FixtureRoot, PathBuf)`. The two callers bind `(_troot, tpath)`.
- **Structs:** `GitFixture`, `ScanFixture`, `TempTree`, `RemovalFixture` and `LifecycleFixture` each hold a `FixtureRoot` field declared last. Their hand `Drop`s only removed the root, so all five are gone. The per-module `NEXT_*` atomic counters went with them, since `FixtureRoot` carries pid and sequence.
- **Canonical form is unchanged:**
  - `LifecycleFixture`, `RemovalFixture` and breadcrumbs' `flush_drops_crumb_of_removed_path` canonicalized before. They still hand out the canonicalized path and keep the `FixtureRoot` alive beside it.
  - `resume_fixture`, `TempTree` and the rest did not canonicalize and still do not.
- **Cleanup lines:** trailing `remove_dir_all` calls are deleted. So are three mid-test ones that ran just before the final asserts, in meta `continue_spawn_...`, git `a_folder_whose_gitfile_points_nowhere_...` and workspace `a_seeded_cache_...`.
- **Every family prefix is kept**, so leftovers stay attributable. Every hunk is inside a `#[cfg(test)]` module.

## Deviations from Plan

1. **[Rule 3] Temporaries would have dropped the root immediately.** `TestRedirect::new(scratch("x-root"))` in `folder_workspace` (13 sites) and `launch` (2), and `std::fs::canonicalize(scratch("removed-path"))` in breadcrumbs, pass the root as a temporary. Converted as-is, the `FixtureRoot` would have been removed at the end of that statement. Each now binds the root to a named local first: `redirect_root` or `fixture_root`. This is the same directory and redirect as before; only its lifetime is now explicit.
2. **[Rule 3] Clone and `PathBuf` call sites.**
   - `FixtureRoot` has no `Clone`, so `test_dir.clone()` in marker (2) and `Some(dir.clone())` in breadcrumbs (7) became `.to_path_buf()`, as the plan's conversion rule allows.
   - The two env values in workspace use `root.path()`.
   - Three test-module imports went unused and were removed: `PathBuf` in marker, folder_workspace and launch. So were the `AtomicU64`/`Ordering` imports and `NEXT_*` statics in git, worktree_scan and lifecycle.
3. **Drop order now removes the root after the guards.** The old hand `Drop` on `RemovalFixture`, `TempTree` and `LifecycleFixture` ran before any field dropped. It removed the root while the redirect was still installed. The plan's rule puts `FixtureRoot` last, so the root is now removed after the redirect and identity guards are restored. `TestRedirect::drop` only restores a thread-local and touches no file, so nothing observable changes. `RemovalFixture`'s doc comment, which claimed the old order, was updated to say this.
4. **Logs:** Task 3's verify sends clippy output to `target/gsd-22.1/04-clippy.log` instead of the terminal. Its exit is still captured on its own statement.
