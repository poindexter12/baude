# Phase 22.1 Plan 03: Fixture root and runtime reaper guards Summary

`FixtureRoot` and `RuntimeReaper` now exist in `baude_core::testing`, and the four leaking PTY and signal fixtures use them. On macOS the outside observer reports `orphans=0 live=0 dirs=0` over all 57 `pty::tests::` and `session::tests::` tests, down from `orphans=1 live=4 dirs=9`. **One blocker found after the plan's own verify:** on Linux the reaper test's shape precondition cannot be met, see Open Items.

## What was built

- `RuntimeReaper::for_identity(&ProcessIdentity)` and `for_pty(&Pty)`. On drop it SIGKILLs `-process_group`. Then, only when `session == leader`, it scans `ps -eo pid=,pgid=,stat=` and SIGKILLs every live pid whose `getsid` is the session. It polls the same scan every 20 ms for up to 5 s, zombies counting as gone, and prints any survivor. It never calls `waitpid` or panics.
- `FixtureRoot::new(prefix)` creates `temp_dir()/<prefix>-<pid>-<seq>`, not canonicalized, after removing any stale copy. It asserts at construction that the prefix starts with `baude-` or `bauded-`. Its drop removes the tree: `NotFound` is fine; on `PermissionDenied` it makes every directory owner-rwx, without following symlinks, and retries once. Any other error is printed. It implements `Deref<Target = Path>` and `AsRef<Path>`.
- Six unit tests in `testing::tests`: two `runtime_reaper_` and four `fixture_root_`.
- Fixtures, all inside `mod tests`:
  - `PtyFixture` holds a `FixtureRoot` declared last; its own `Drop` is gone.
  - `kill_reaps_live_child` and `pre_exec_registration_gate_owner_death_and_release` bind `RuntimeReaper::for_pty(&pty)` right after the spawn.
  - `signal_fixture` and `hup_trapping_fixture` return `(FixtureRoot, TestRedirect, Pty)`; callers bind `(_root, _redirect, pty)`.
  - `session_kill_reaps_both_children` binds an agent reaper and a shell reaper before it builds the `Session`.
  - `group_extinction_root` returns a `FixtureRoot`.
- Drop order was checked with a throwaway rustc probe: later tuple fields and later bindings drop first, so the Pty drops, then the redirect, then the root.

## Deviations from Plan

1. **[Rule 2] Extra signal guards in the reaper.** Besides the planned gate, it never signals pgid 0 or 1, which `kill(-pg)` would turn into the caller's group or every process. It also never signals the harness's own group or session, or its own pid. This is T-22.1-09, made stricter. aba7895.
2. **[Rule 2] FixtureRoot prefix must be a single path component.** A prefix containing `/` or `..` is rejected, and the drop re-checks the name, so T-22.1-10 also holds against `baude-../x`. 2b3ed13 and 8c96e6f.
3. **The poll re-kills.** Each poll pass SIGKILLs the live members it finds, not only the first scan. This is within the interface: same gate, same membership rule.
4. **The reaper test in Task 1 used a hand-made root** because `FixtureRoot` did not exist yet. Task 2's GREEN commit moved it to `FixtureRoot`.
5. **RED runs used a fresh scratch `TMPDIR`**, so litter from the failing tests stayed out of the shared temp dir. Each was removed afterwards. Nothing else about the commands changed.
6. **`group_extinction_root`** is the "baude-{label} root near line 1637". The before-run named its two roots, `group-drain` and `group-error-path`.

## Open Items

- **BLOCKER for Linux CI: the reaper test's shape cannot be built on Linux.** I ran the six testing tests plus the pty and session tests in `baude-gate`, which is `rust:1-bookworm` as uid 1000, under the leftover check, not through `gate.sh`. The result was `67 passed; 1 failed` and `command=101 orphans=0 live=0 dirs=0` (`target/gsd-22.1/03-linux.log`). The failure is the planned precondition: `no member of session 1024 outside group 1024 appeared within 5 s`.
  - Cause, from a probe in the same image (`target/gsd-22.1/03-linux-probe.log`): bookworm's bash 5.2.15 execs the last command of a `-c` string, so `sleep 30` becomes the session leader itself, `10 8 10 10 Ss+ sleep 30`. macOS `/bin/bash` is 3.2.57, which forks it into a job-control group. With `trap '' HUP; sleep 31; true`, bash 5.2 builds the macOS shape: bash `18 18 18`, `sleep 31` in pgid 19, session 18.
  - So on Linux the four named leaks do not happen at all, and the precondition is wrong about that host. Per instructions I did not change the committed test.
  - Proposed fix, not applied: spawn `trap '' HUP; sleep 30; true` in `runtime_reaper_kills_job_control_children_in_the_recorded_session`. The precondition and the survivor assertion stay as they are, and the test then builds the job-control shape on both bash versions. It needs a decision before 22.1-06 wires anything into CI.
- **Not recorded in `.planning/WINDOWS.md`.** The orchestrator restricted staging to this plan's files, so the blocker above is recorded only here.
- The Linux run also showed the panic path removing its root: the failing test's `FixtureRoot` left `dirs=0`.
