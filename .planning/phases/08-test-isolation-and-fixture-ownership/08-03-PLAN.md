<objective>
Make workspace identity resolvable per fixture instead of once per process, so concurrent
fixtures cannot share or race one identity seeded from the developer's real environment.

Purpose: `ACTIVE: OnceLock<Workspace>` is the last process-wide cache in the isolation
path. Whichever fixture calls `active()` first pins the identity for the whole test binary,
and that identity is derived from the developer's real config. Because
`git::managed_default_worktree_path` composes `<base>/<workspace>/repository-<key>`, a
pinned identity also pins the directory every later fixture writes into.

Output: a thread-local override checked ahead of the retained `OnceLock`, and `initialize`
taking its config by parameter.
</objective>

<research_deviations>
**`active()` returns `&'static Workspace`, which a `thread_local!` cannot hand out.**
D-07 locks the signature, and a thread-local cannot produce a `&'static` reference to its
own contents. The resolution, compiled and verified in RESEARCH Finding 3, is to leak the
per-fixture `Workspace` with `Box::leak` and store the resulting `&'static` reference —
which is `Copy`, so a `Cell` suffices and no `RefCell` borrow can escape.

This is a genuine leak, and it is acceptable here for two reasons that must both hold:
it is bounded by fixture count rather than by call count, and it lives entirely inside
`cfg(any(test, feature = "test-support"))` code, so it never reaches a shipped binary.
`Workspace`'s fields are already `'static`-compatible (`String`, `&'static dyn Backend`,
`Option<String>`, `Option<u16>`), so nothing about the type needs to change.

**D-08 requires an identity override, independently of filesystem containment.** A cached
workspace has no reliable fixture provenance. An override-free test must panic before
consulting `ACTIVE`, including when another caller already populated it. The dogfood child
remains environment-contained for filesystem resolution, but holds its own literal-config
identity guard for its test body. No new runtime flag or exception to D-08 is needed.
</research_deviations>

<decision_collision>
## D-06 and D-07 are satisfied by explicit initialization and a reader-only `active()`

`active() -> &'static Workspace` keeps its existing signature (D-07), but no longer lazily
initializes. It first reads the thread-local override in support builds. If missing, a
support-build escape assertion panics naming workspace identity, before any `ACTIVE.get()`
lookup. In production, `ACTIVE.get().expect(...)` returns the explicitly initialized
workspace or reports a missing-startup-initialization programmer error. Neither branch
loads config, resolves roots, or calls `initialize` (D-06, D-08).

`initialize(config: &Config, hint: Option<&str>) -> &'static Workspace` has distinct storage
paths: production resolves the existing environment/config/hint precedence into `ACTIVE`;
support builds require a held fixture identity guard, resolve from the supplied literal
and hint (no ambient workspace/backend env), and update that thread's override only. It
never writes `ACTIVE` in support builds. Reinitializing one fixture cannot affect another.
The outer identity guard still restores its saved reference on drop.

`override_for_test(config: &Config, hint: Option<&str>) -> TestRedirect` is the explicit
fixture constructor in `workspace.rs`. It uses `resolve_with_hint(None, None, hint, config,
...)`, leaks one resolved workspace, and returns plan 01's `TestRedirect::with_workspace`.
Repeated `active()` calls allocate nothing. This is the same unified guard storage, not an
independent thread-local. Fixture owners hold the root guard first and the identity guard
second, and drop identity before root to preserve nested restoration.

Task 1 makes the core reader/seeder changes together, and runs only core identity tests.
Task 2 updates both binary startup entry points and app/API/UI fixture owners. Manager
owners are migrated in plan 06 task 1. Plan 08 completes worker/subprocess isolation before
any App-construction or PTY regression runs; this plan's executed fixture filters inspect
only held owners, identity and managed paths, without constructing App or spawning PTYs.
Broad tests cannot run until all of these migrations land.
A missing startup call is fixed at that entry point, never by adding an implicit config
read to `active()`. This is a grounded implementation choice, not a decision amendment.
</decision_collision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test fixture -> process-wide identity cache | A single `OnceLock` write by the first fixture determines the directory every later fixture in that binary writes into |
| developer real config -> test identity | Identity seeded from `load_config()` imports the developer's configured workspace name into the test's path composition |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-05 | Tampering | `workspace::ACTIVE` `OnceLock` | high | mitigate | Thread-local override consulted before the `OnceLock`; concurrency test proves two fixtures resolve independently (task 1) |
| T-08-06 | Information Disclosure | identity seeded from the developer's real config | high | mitigate | `initialize` takes config by parameter so fixtures supply a literal and the identity path performs no config read (task 2) |
| T-08-07 | Denial of Service | `Box::leak` per fixture | low | accept | The leak is bounded by fixture count, not call count, and is confined to test-support-gated code that never ships; documented in the task action |
| T-08-24 | Information Disclosure | uninitialized or override-free identity access | medium | mitigate | Reader-only `active` performs no config read; support builds panic before cache lookup, production requires explicit startup initialization, and thread-local instrumentation measures no-read execution (tasks 1, 2) |
| T-08-11 | Tampering | `managed_default_worktree_path` composition | medium | mitigate | Direct assertion that the composed path is unchanged for a fixed identity and key (task 1) |
</threat_model>
