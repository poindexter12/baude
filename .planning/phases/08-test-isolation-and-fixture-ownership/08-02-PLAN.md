<research_deviations>
**No existing test writes a VAPID key — this refactor fixes no currently failing test.**
CONTEXT.md's evidence section reports `~/.config/baude/daemon-vapid.json` as a "real VAPID
keypair written by tests." The call graph does not support that: `Vapid::load_or_generate`
has exactly one caller (`push.rs:197`), `PushState::load` has exactly one caller
(`bauded/src/main.rs:182`, production), no test constructs a `PushState`, the `/push/*`
routes have no test coverage at all, and the on-disk file predates the current suite.

The D-02 refactor is still required by Success Criterion 1 — it removes the duplicate
resolver that would defeat a core-only redirect. But a plan that accepted "existing tests
stop writing VAPID keys" as its acceptance signal would verify nothing, because no such
test exists to change behavior. Task 2 therefore **adds** the first coverage of this
subsystem and asserts positively that both files land inside the fixture root.

Note also that `PushState::load(false)` still calls `Vapid::load_or_generate()`
unconditionally — the `persist` flag suppresses subscription reads and writes but not key
generation. Passing `false` in a test is not a substitute for the redirect and must not be
used as one.
</research_deviations>
