<interface_from_prior_plan>
Plan 01 delivers, in `baude_core::testing`, behind `cfg(any(test, feature =
"test-support"))`:

- `pub struct TestRedirect` — RAII, `#[must_use]`, `TestRedirect::new(root)`, reverts on drop.
- `claude_config_dir_override() -> Option<PathBuf>` — the reader this plan's `meta.rs`
  change consumes.
- `pub(crate) fn assert_contained(resolved: &Path, what: &str)` — panics unless the
  resolved real path sits inside `BAUDE_TEST_FIXTURE_ROOT`.
- `pub struct NoFixtureRoot` — RAII, `#[must_use]`, thread-local; makes `assert_contained`
  observe no fixture root on the current thread only. The escape-test mechanism, replacing
  any process-wide clearing of `BAUDE_TEST_FIXTURE_ROOT`.

`baude` and `bauded` are binary-only crates, so their test targets are selected with
`--bins`, never `--lib` (plan 01 `<crate_shape>`). No verify command pipes a gate into
another command, because a pipeline reports the last stage's exit status and masks failure.

`baude-core/Cargo.toml` declares `[features] test-support = []`, and `bauded/Cargo.toml`
already carries `baude-core = { workspace = true, features = ["test-support"] }` under
`[dev-dependencies]`.
</interface_from_prior_plan>

<research_deviations>
**No existing test writes a VAPID key — this refactor fixes no currently failing test.**
CONTEXT.md's evidence section reports `~/.config/baude/daemon-vapid.json` as a "real VAPID
keypair written by tests." The call graph does not support that: `Vapid::load_or_generate`
has exactly one caller (`push.rs:197`), `PushState::load` has exactly one caller
(`bauded/src/main.rs:182`, production), no test constructs a `PushState`, the `/push/*`
routes have no test coverage at all, and the on-disk file predates the current suite.

The D-02 refactor is still required by Success Criterion 1 — it removes the duplicate
resolver that would defeat a core-only redirect. But a plan that accepted "existing tests
stop writing VAPID keys" as its acceptance signal would verify nothing, because no such
test exists to change behavior. Task 2 therefore **adds** the first coverage of this
subsystem and asserts positively that both files land inside the fixture root.

Note also that `PushState::load(false)` still calls `Vapid::load_or_generate()`
unconditionally — the `persist` flag suppresses subscription reads and writes but not key
generation. Passing `false` in a test is not a substitute for the redirect and must not be
used as one.
</research_deviations>

Apply the same split plan 01 applied to `persist::config_base()`. Extract the existing real
resolution into a private `real_claude_config_dir()`, reproducing its chain verbatim:

consults `CLAUDE_CONFIG_DIR` where the others consult `XDG_*`, and its terminal fallback
differs from both `persist.rs` and `git.rs`. Collapsing them changes production behavior.

`CLAUDE_CONFIG_DIR` being first is also why plan 01 task 3 had to set it on the dogfood
child's `Command`: a developer who exports it in their shell — which is documented setup on
this machine — would otherwise have the child resolve their real config directory and trip
`assert_contained`. Plan 06 reruns the dogfood regression after both this resolver and
plan 03's identity consumers are isolated; do not run it in concurrent wave 2.

Then rewrite `claude_config_dir()` to return `testing::claude_config_dir_override()` when
one is set, and otherwise call `real_claude_config_dir()` followed by
`testing::assert_contained(&real, "claude config dir")` under the
`cfg(any(test, feature = "test-support"))` gate.

Isolating by redirect rather than by parameter is the locked choice (D-03) precisely
because it avoids reshaping `ClaudeMeta::poll`: both call sites keep their current
signatures and neither gains an `_at` variant. Do not add one.

Add the behavior tests above to `meta.rs`'s test module. Use nested synthetic root guards
for restoration; after the outermost guard drops expect the escape panic, never call the
real resolver to compare developer paths. Name the new contained cases with the
`claude_config_dir_` prefix; a synthetic session-data poll fixture covers both poll paths.
The unguarded case is
`#[should_panic]` with an expected-message substring and holds plan 01's thread-local
`NoFixtureRoot` probe. It must not clear `BAUDE_TEST_FIXTURE_ROOT` or mutate any other
environment variable: that is a process-wide change, and no mutex can contain it because the
concurrently running tests that would observe it never take the lock. The probe is
thread-local, so this test needs no serialization at all.
