<objective>
Build the hook foundation: a new `baude-core/src/hook.rs` module with pure, testable transforms (`build_event`, `merge_hook_settings`) plus thin IO helpers (`event_path`, `append_event`), wire the `baude hook` subcommand dispatch in the `baude` binary, and seed each TUI-spawned session's `.claude/settings.local.json` so Claude Code actually invokes the hook.

Purpose: This is the keystone of HOOK-01 (idempotent settings seeding that never clobbers user config) and the TUI-local half of HOOK-03 (file-tail transport). Everything downstream (event consume, daemon endpoint) depends on the event-line schema and the `event_path`/`append_event` seam defined here.

Output: `baude-core/src/hook.rs` (new, fully tested), `pub mod hook` in `lib.rs`, a `hook` dispatch arm in `baude/src/main.rs`, and a seeding call in `baude/src/app.rs::add_session`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude Code -> `baude hook` stdin | Untrusted (schema-drifting) JSON payload crosses into baude |
| `session_id` -> `/tmp/baude-events-<sid>.jsonl` path | Attacker-influenced string used in filesystem path construction |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering / DoS | `event_path(sid)` filesystem path from hook `session_id` | mitigate | Build path strictly under `/tmp`; reject/sanitize `sid` containing `/` or `..` before formatting (defense-in-depth, mirrors `bridge_path` posture). V5 input validation. |
| T-02-02 | Denial of Service | `build_event` / `main.rs` hook arm parsing untrusted stdin | mitigate | Untyped `Value` accessors + `unwrap_or(json!({}))`; `baude hook` always `exit(0)`, never non-zero (non-zero blocks Claude). |
| T-02-03 | Elevation of Privilege | Seeded `command` in user `settings.local.json` | accept | baude inserts only its own `current_exe() hook` command; never copies untrusted commands. User's own hooks preserved but not introduced by baude. |
| T-02-04 | Tampering | Clobbering user `statusLine`/hooks during merge | mitigate | `merge_hook_settings` only `.entry().or_insert()` into `hooks.<event>` arrays via sentinel-guarded append; sibling keys untouched. Required preserve-user-settings test (HOOK-01). |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependencies this phase (RESEARCH Package Legitimacy Audit: none). No install tasks; no [ASSUMED]/[SUS] packages. |
</threat_model>
