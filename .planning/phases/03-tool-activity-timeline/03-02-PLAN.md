<objective>
Expose the Phase-1 ring over the daemon REST surface (ACT-02): a `GET /sessions/{id}/activity` JSON endpoint with an optional clamped `?limit`, and a standalone `GET /sessions/{id}/activity-stream` SSE channel that offset-tails the on-disk `/tmp/baude-events-<sid>.jsonl` file (a near-verbatim clone of `api.rs::stream()`), plus a bounded `activity[]` on `SessionInfo` so the remote TUI overlay rides the existing `/sessions` poll.

The single genuine pitfall: the SSE channel must NOT reuse `transcript::Tail` — that tail runs each line through `parse_line` (transcript schema) and would yield zero events for hook lines. Copy the offset-tail skeleton and swap ONLY the per-line parse to yield `HookEvent` (Pitfall 1).

Purpose: Without this, the PWA (03) and the remote TUI (04) have nothing to fetch or stream. This is the server half of the feed.

Output: `Manager::event_path` + `Manager::activity` accessors, `SessionInfo.activity`, the two routes/handlers, a `HookEvent`-yielding event-line tail, the `notify.rs` test-constructor fix (Pitfall 3), and integration tests via tower `oneshot`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → daemon REST/SSE | `{id}` path param and `?limit` query param cross from an (unauthenticated, tailnet-bound) client |
| event JSONL file → SSE tail | On-disk lines (schema drift / truncation) cross into the streamed HookEvent serialization |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Information Disclosure | unauthenticated GET /activity and /activity-stream reachable | accept | Inherits the project tailnet/loopback bind (default 127.0.0.1:8642); no auth layer by design (REQUIREMENTS Out of Scope; same disposition as Phase-2 T-02-08). No new exposure beyond the existing REST surface. |
| T-03-05 | Tampering | path injection via session id into the /tmp event path | mitigate | `event_path` resolves through `baude_core::hook::event_path`, which already replaces `..`/`/` (hook.rs:44-47, Phase-2 T-02-01); `Path<u64>` rejects non-numeric ids at the framework layer. |
| T-03-06 | Denial of Service | unbounded `?limit` exhausting memory/response | mitigate | `limit = q.limit.unwrap_or(ACTIVITY_CAP).min(ACTIVITY_CAP)` clamp; the ring is itself capped at ~200 so the response is bounded regardless. |
| T-03-07 | Denial of Service | malformed/oversized event line on the SSE tail | mitigate | `parse_event_line` is untyped-`Value`-or-skip, complete-lines-only, truncation-reset; never panics (mirrors `read_event_tail` T-02-05). No 500 path. |
| T-03-08 | Denial of Service | unbounded SSE connection growth | mitigate | Each stream offset-tails one file at `STREAM_POLL_MS` and ends via the `Err(_) => break` guard when the session is deleted — same lifecycle as `stream()`. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No installs this phase (03-RESEARCH.md Package Legitimacy Audit: none); all deps are existing vetted workspace crates. |
