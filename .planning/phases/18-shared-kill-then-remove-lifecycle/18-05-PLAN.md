<objective>
Pin the persistence and ordering contract of `removal::remove` with injected `AtomicFailure`s and fixture-level faults: every `AtomicFailure` variant has a test (rename and sync keep the prior state, directory-sync commits a degraded result, refused-row names the row), the save closure runs once per call, a crash between disk delete and save leaves a file that still parses to the prior consistent state for both a checkout target and a repository mid-fan-out, a disk failure mid-fan-out is retryable, and candidate validation refuses before anything irreversible. These are the RMV-06 and SC5 guarantees the CONTEXT accepted without an intent journal; proving them on fixture output is what makes that acceptance safe.

Purpose: the save stage is the one place the phase can corrupt durable state, and the ordering of validation against kill and delete is the one place a refusal could arrive too late; this plan exercises every branch of both against real files written by `persist::save_current_at_test` and real process doubles.
Output: nine tests in `removal::tests` and any fix they force in `persist_stage`, `disk_stage` or the candidate validation step.
</objective>
