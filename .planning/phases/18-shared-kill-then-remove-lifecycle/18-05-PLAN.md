<objective>
Pin the persistence contract of `removal::remove` with injected `AtomicFailure`s: rename failure keeps the prior state, directory-sync failure commits a degraded result, the save closure runs once per row set, and a crash between disk delete and save leaves a file that still parses to the prior consistent state and reconciles the missing child. These are the RMV-06 and SC5 guarantees the CONTEXT accepted without an intent journal; proving them on fixture output is what makes that acceptance safe.

Purpose: the one place the phase can corrupt durable state is the save stage; this plan exercises every branch of it against real files written by `persist::save_current_at_test`.
Output: four tests in `removal::tests` and any fix they force in `persist_stage`.
</objective>
