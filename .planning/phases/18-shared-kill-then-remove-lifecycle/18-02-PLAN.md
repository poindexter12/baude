<objective>
Add the force removal primitive for managed worktree directories to `baude-core/src/git.rs`, beside `remove_verified_worktree`, so plan 04's disk stage has one call that enforces managed-root containment, re-proves repository identity and registration on the live tree, inspects the target's `.git` shape (symlink, directory, bare signature, malformed gitfile) before spawning git, runs `git worktree remove --force --force -- <path>`, falls back to delete-plus-prune only for a registered linked worktree of this repository inside the managed root, and proves its postcondition from `git worktree list`.

Purpose: D-RMV-01 says explicit removal bypasses the clean-tree preflight and a runtime holding the tree as cwd does not block it; D-RMV-07 says no branch is ever deleted; the CONTEXT disk rule says the fallback may delete only inside baude's managed worktree root. Bypassing cleanliness and lock does not license dropping the ownership checks the verified path performs: the clean-tree preflight lives in `inspect_removal` / `topology_blockers` (not inside `remove_verified_worktree` as CONTEXT's wording suggests), so this helper avoids the inspect path while re-running the identity, main-worktree and registration checks itself. The private postcondition helpers live in `git.rs`, so the primitive must too (RESEARCH Pattern 3). Inputs and outputs are crisp, so this is a TDD feature.

Output: `remove_managed_worktree_forced` plus its result and error types and twenty-three fixture-backed tests in `git::tests::forced_removal`.
</objective>
