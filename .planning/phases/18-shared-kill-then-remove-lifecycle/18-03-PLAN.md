<objective>
Generalize the single-row `RepositoryState::remove_standalone_session` into a batch `remove_rows` that removes checkouts, repositories and standalone sessions by key in one call and returns the removed rows for the report. This is the aggregate-side half of the identity-model generalization: one mutation covers all four row kinds so plan 04 can clone, mutate, validate and save in one statement.

Purpose: D-RMV-06 requires one atomic save per removed row set and SC5 forbids a parent without children or a child without its parent. `validate()` catches a dangling child but permits a childless parent, so the only safe shape is a batch removal of the whole set followed by `validate()` (RESEARCH Pitfall 5). Pure data transformation with explicit I/O: TDD.
Output: `RemovedRows` and `RepositoryState::remove_rows` with four unit tests in `repository::tests`.
</objective>

<feature>
  <name>Batch row removal on the RepositoryState aggregate</name>
  <files>baude-core/src/repository.rs</files>
  <behavior>
    Using the existing test builders in `repository::tests` (`repository(key, order)`, `checkout(key, repository_key, order)`, `standalone(key, path, order)`):
    - State with repository k (checkouts c1, c2), repository j (checkout c3), standalone s. `remove_rows(&[k], &[c1, c2], &[])` returns `RemovedRows { repositories: [k row], checkouts: [c1 row, c2 row], standalone_sessions: [] }`; afterwards `state.repositories` has only j, `state.checkouts` has only c3, `state.checkouts.iter().any(|c| c.repository_key == k)` is false, `state.validate()` is `Ok(())`, and all four `next_*` counters equal their pre-call values.
    - Same state, `remove_rows(&[k], &[], &[])` leaves c1 and c2 in place and `state.validate()` returns `Err(ValidationError::DanglingRepositoryKey(k))`.
    - `remove_rows(&[RepositoryKey::from_raw_for_test(999)], &[unknown checkout], &[unknown standalone])` (or the builders' equivalent for an unused key) returns an empty `RemovedRows`, leaves `state` equal to its pre-call clone, and keeps every counter.
    - `remove_rows(&[], &[], &[s])` returns the standalone row in `standalone_sessions` and `state.standalone_sessions` is empty; `validate()` is `Ok(())`.
  </behavior>
  <implementation>
    In `baude-core/src/repository.rs`, directly after `remove_standalone_session` (line 870-879):
    - `#[derive(Clone, Debug, Default, PartialEq, Eq)] pub struct RemovedRows { pub repositories: Vec<SavedRepository>, pub checkouts: Vec<SavedCheckout>, pub standalone_sessions: Vec<SavedStandaloneSession> }`.
    - `pub fn remove_rows(&mut self, repositories: &[RepositoryKey], checkouts: &[CheckoutKey], standalone: &[StandaloneKey]) -> RemovedRows`: partition each Vec with `retain`-style iteration that moves matching rows into the result in state order (use `std::mem::take` plus `into_iter().partition(|row| keys.contains(&row.key))` to keep order and avoid index shifting); never modify the `next_*` counters; do not call `validate()` inside (the caller validates the whole clone once).
    - Doc comment: this is the one mutation removal uses for every row kind; callers remove the full parent-plus-children set in one call because `validate()` rejects a dangling child but not a childless parent.
    - Keep `remove_standalone_session` in place (existing callers); optionally reimplement its body as `self.remove_rows(&[], &[], &[key]).standalone_sessions.pop()`.
  </implementation>
</feature>
