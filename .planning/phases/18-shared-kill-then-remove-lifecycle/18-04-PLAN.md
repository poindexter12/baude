<objective>
Add the one public removal operation, `removal::remove`, composing the three stages in the locked order: kill every targeted runtime through `Session::kill_and_wait`, force-remove managed worktree directories through `git::remove_managed_worktree_forced`, then one atomic save of the whole removed row set through a caller-supplied closure, committing the in-memory state only when that save succeeds. This completes the identity-model generalization started in plan 01: one entry point handles a repository parent, a main checkout, a managed worktree child, an unmanaged checkout and a standalone folder, with the per-kind disk rule already classified by `select_rows`.

Purpose: KILL-01/02/03 fix the kill semantics (group SIGTERM then SIGKILL, reaped, survivor leaves the row), RMV-06 fixes one save per row set, RMV-05 fixes the shared report. Pure orchestration over tested primitives with crisp observable outcomes (process state, directory presence, file bytes, report fields), so TDD with real process doubles per the fixture-realism rule.
Output: `RowRuntime`, `remove` and five live-fixture tests in `removal::tests`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied Session handles -> signals | the handle decides which process group receives SIGTERM/SIGKILL |
| removal -> state file | one rename-based write replaces the durable aggregate |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-09 | Spoofing | kill_stage handle matching | high | mitigate | A handle is accepted only when its RowKey matches and `session.claude.process_identity().pid` equals the persisted runtime pid; `Pty::kill_and_wait` then re-verifies the live identity (start time, pgid) before signalling, so a reused pid is never signalled (test `missing_runtime_handle_is_typed_error_before_any_kill`) |
| T-18-10 | Tampering | kill failure path | high | mitigate | `RuntimeSurvived` returns before the disk and persist stages; the state file and in-memory aggregate are untouched (tests `surviving_runtime_leaves_row_and_disk`, `parent_kill_failure_aborts_before_disk_and_state`) |
| T-18-11 | Denial of service | partial disk stage then save failure | medium | accept | Disk changes before a failed save are recovered by startup reconcile (Protected(Missing)) and by a retry that reports the rows as already removed; an intent journal is out of scope by decision |
| T-18-SC | Tampering | cargo dependencies | high | mitigate | No new crate (libc and serde already present); any `Cargo.toml` change is a planning deviation requiring a blocking human checkpoint |
