<objective>
Add the one public removal operation, `removal::remove`, composing the stages in the locked order: prove handle ownership and candidate validity, kill every targeted runtime through `Session::kill_and_wait`, force-remove managed worktree directories (and prune already-missing ones) through `git::remove_managed_worktree_forced`, then one atomic save of the whole removed row set through a caller-supplied closure, committing the in-memory state and consuming the runtime handles only when that save succeeds. This completes the identity-model generalization started in plan 01: one entry point handles a repository parent, a main checkout, a managed worktree child, an unmanaged checkout and a standalone folder, with the per-kind disk rule already classified by `select_rows`.

Purpose: KILL-01/02/03 fix the kill semantics (group SIGTERM then SIGKILL, reaped, survivor leaves the row), RMV-06 fixes one save per row set, RMV-05 fixes the shared report. Pure orchestration over tested primitives with crisp observable outcomes (process state, directory presence, file bytes, report fields, handle ownership), so TDD with real process doubles per the fixture-realism rule.
Output: `RowRuntime`, `remove` and nine live-fixture tests in `removal::tests`.
