<objective>
Create `baude-core/src/removal.rs` with the shared removal vocabulary (target, row key, disk action, planned set, report, error) and the two pure functions every caller needs first: `select_rows` and `preview_removal`. This is the identity-model decision for the phase made explicit: removal generalizes from one row kind (`remove_standalone_session`) to all four row kinds (repository parent, main checkout, managed worktree child, unmanaged checkout, standalone folder), and the per-kind disk rule is a data classification (`DiskAction`) computed once and reused by preview and by the real run.

Purpose: Phase 20 (TUI) and Phase 21 (daemon REST) must describe exactly what a removal will do before doing it (CONTEXT "side-effect-free preview"), and RMV-05 requires one shared `baude-core` operation. Selection and classification are business logic with crisp input/output, so TDD fits: write the classification table as tests, then implement.
Output: `baude-core/src/removal.rs` (types + `select_rows` + `preview_removal` + unit tests), `pub mod removal;` in `baude-core/src/lib.rs`.
</objective>
