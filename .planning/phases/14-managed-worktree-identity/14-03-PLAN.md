  <action>
    Update README.md Worktrees section to document (per design answer 5 ownership policy):
    
    1. **Identity scheme:** Managed worktree directories are identified by a stable digest of the repository's canonical git common directory (output of `git rev-parse --git-common-dir`). The digest is the first 12 characters of the SHA256 hash, formatted as `repository-<12 hex digits>/<role>-<checkout_key>`. This ensures two processes admitting the same repository derive the same path without coordination.
    
    2. **Legacy migration:** Existing counter-based directories (`repository-1`, `repository-2`, etc.) from earlier baude versions are recognized in place. The system reads a small `.baude-marker.json` file inside each managed directory to record and verify ownership. On first admission of a legacy directory, baude automatically writes a marker; after a state file reset, markers enable recovery without a scan.
    
    3. **Collision handling:** If two repositories converge on the same path (rare but possible under legacy counters), baude detects the collision via the marker file and allocates the newcomer a distinct digest-keyed directory (`repository-<12hex>-2`, etc.). The collision is reported non-destructively in `baude worktrees scan --json` output with the owning repository named. Users see only the assigned repository key in text output (not the canonical git path).
    
    4. **Path stability:** After a state file reset, the same repository is found again by computing its digest from the canonical git common directory; no scan is required for recovery.
    
    Integrate this into the existing Worktrees section without breaking the existing prose about repository rows, worktree removal (x and X), and git semantics.
  </action>
