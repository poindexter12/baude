## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Path parsing | repository_key function must accept both legacy and new formats; malformed input must be rejected. |
| Marker read during collision detection | Malformed marker must not crash; treat as ownership unknown and continue. |
| Legacy dir discovery | Must not follow symlinks out of the managed worktree base during checkout discovery. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-06 | Tampering | Path parsing round-trip | medium | mitigate | Round-trip check `format!("repository-{key}") == name` prevents aliases and parsing ambiguities. |
| T-14-07 | Tampering | Collision detection bypass | medium | mitigate | Marker is source of truth; if missing, discover owner from git checkouts inside directory (fail-closed). |
| T-14-08 | Denial of Service | Legacy discovery walks unbounded directories | medium | mitigate | Only examine subdirectories matching primary-* or *-* patterns; limit to one level. |
| T-14-09 | Information Disclosure | Canonical dir in collision report | medium | mitigate | Report is internal; user sees only "repository-<digest>" display in TUI. Canonical dir logged only in daemon debug output. |
