<objective>
Create `baude-core/src/suppression.rs`: the per-workspace advisory store that remembers checkout paths removed while their repository row survived, so `admit_existing_worktrees` can skip them on the next relaunch, and that forgets a path on explicit admission or on parent removal. This plan delivers the file format and the five helpers with full unit coverage; plan 04 wires the writes into the clearing stage and plan 05 wires the consult and lift into the TUI.

Purpose: READM-03 names the third place a removed row can come back from: the `git worktree list` sweep that runs on every admission of an already-known repository. Bindings and markers do not cover it (D-09). The store has crisp input/output (key present, key absent, file absent, file corrupt) and so is a TDD feature in its own right.
Output: `suppression.rs` with `SCHEMA_VERSION`, `FILE_BASE`, `SuppressionFile`, `SuppressionEntry`, `file_path`, `is_suppressed`, `lift`, `suppress`, `drop_children`, registered in `lib.rs`, plus the five tests named below.
</objective>

<feature>
  <name>Per-workspace suppression store (consult, lift, suppress, garbage-collect)</name>
  <files>baude-core/src/suppression.rs, baude-core/src/lib.rs</files>
  <behavior>
    - `suppress(root, path, common_dir, 10)` then `is_suppressed(root, path)` is true; the file at `file_path(root)` parses as `SuppressionFile` with `schema_version == SCHEMA_VERSION` and one entry whose key is `folder_key(path)`, `repository_common_dir == folder_key(common_dir)`, `suppressed_ms == 10`
    - `lift(root, path)` returns `Ok(true)` and `is_suppressed` becomes false; a second `lift` returns `Ok(false)` and the file bytes are unchanged; `lift` on an absent file returns `Ok(false)` and the file stays absent
    - With two entries under common dir A and one under B, `drop_children(root, A)` returns `Ok(2)`, leaves B's entry equal to its pre-call value, and `drop_children(root, A)` again returns `Ok(0)`
    - A file containing `{not json` makes `is_suppressed` return false; the next `suppress` replaces it with a valid file holding only the new entry
    - `file_path(root)` starts with `root`, has a `.json` extension and a file name containing `FILE_BASE`, and differs from the breadcrumbs file name
  </behavior>
  <implementation>Copy the derive set and serde attributes of `FolderWorkspaceFile` (`#[serde(default = "schema_version_default")] schema_version`, `#[serde(default)] entries: BTreeMap<String, SuppressionEntry>`). All helpers take `root: &Path` explicitly so tests and callers pass `persist::config_dir()` or a scratch dir; the file name comes from `crate::workspace::active().state_file(FILE_BASE)`. Reads use `breadcrumbs::load_json` (corrupt or absent reads as default). Writes use `breadcrumbs::locked_merge_write` with a `load_json` pre-check so `lift` and `drop_children` do not write when nothing changes.</implementation>
</feature>
