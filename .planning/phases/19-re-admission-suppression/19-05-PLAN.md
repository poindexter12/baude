<objective>
Wire the suppression store into the TUI's admission path: skip suppressed worktrees in the inventory sweep, and lift an entry on explicit admission of exactly that path through any of the three local routes, so the fresh row is admitted in the same pass with new identity.

Purpose: READM-03's read side and READM-04. Plan 02 built the store; without this plan nothing consults it. The behaviours are observable on `App::repository_state` after a call, so they are written as failing `App` tests first using the existing `admission_repo` fixtures.
Output: the consult, a `lift_suppression` helper called from `admit_repository` and `admit_standalone`, and five `App` tests.
</objective>

<feature>
  <name>Suppression consult in the sweep and lift on explicit admission</name>
  <files>baude/src/app.rs</files>
  <behavior>
    - Given a repository with two linked worktrees and a suppression entry for one of them, `app.admit_repository(&root)` admits the other worktree and the main checkout but no row has `observed_path == suppressed`
    - Given the same entry, `app.admit_repository(&suppressed_worktree)` (what `n` with that path reaches) lifts the entry (`is_suppressed` false) and admits the row with a `CheckoutKey` and `first_seen_order` greater than every pre-existing one, `session.resume_id == None`, `owned_runtime().is_none()`, lifecycle Inactive for the sweep-admitted siblings
    - `app.admit_repository(&root)` with a child entry present leaves `is_suppressed(child)` true and the child absent
    - A second `App::new(child.join("src"))` (a subfolder inside the suppressed checkout) followed by `restore()` lifts the entry and admits the checkout through the `LaunchDirectory` route; `app.open_repo_session_via(dest, LocalAdmissionRoute::CloneCompletion)` after cloning into a suppressed `dest` lifts it too
    - With the suppression file's lock path pre-created as a directory, `admit_repository(&suppressed_worktree)` still returns Ok, the row is admitted, and the last message mentions the lift failure
  </behavior>
  <implementation>Add `fn lift_suppression(&mut self, path: &Path)` on `App`: compute `key_path = baude_core::git::repo_root(path).unwrap_or_else(|| path.to_path_buf())`, call `baude_core::suppression::lift(&baude_core::persist::config_dir(), &key_path)`, and on `Err(e)` call `self.set_message(format!("suppression lift failed: {e}"))`. Call it in `admit_repository` right after `let snapshot = git::discover_repository(path)?;` and in `admit_standalone` right after `canonical` is computed. In `admit_existing_worktrees`, after `if owned { continue; }`, add the `is_suppressed` check with `continue`.</implementation>
</feature>
