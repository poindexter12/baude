<objective>
**Startup path with incremental restore and bounded keyboard probe:** Implement non-blocking first-frame rendering by deferring session restore to the main loop (one per iteration), bind the keyboard probe to 250 ms with fallback to legacy encoding, and batch durable state writes until restore completes. Expose startup timing on the daemon /info endpoint.

**Purpose:** Unbatched restore writes (3-5 fsyncs per session) block the main thread for 10+ seconds on 100 sessions. Incremental restore maintains input responsiveness and shows progress. Keyboard probe timeout was 2 s; 250 ms bound allows terminal negotiation to fail fast. Batched writes reduce fsync calls from 300+ to 1.

**Output:** Non-blocking incremental restore state machine, 250 ms bounded probe with legacy fallback, batched durable writes guarded by restoring flag, and daemon /info timing exposure.
</objective>
