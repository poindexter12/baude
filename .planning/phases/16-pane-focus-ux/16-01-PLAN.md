<threat_model>
## Focus State Consistency

**Threat:** Focus state becomes inconsistent (e.g., focused on Shell but shell is not open, or shell exited while focused).

**Mitigations:**
- Always check `shell_open && shell.is_some()` before preserving Shell focus
- Fallback to Claude on any state inconsistency
- toggle_shell already handles close-while-focused fallback (unchanged)
- selection_reconcile checks and resets focus if session is lost (unchanged)

**Verification:** Tests assert focus fallback when shell is not available; tests mock shell-exited scenarios.

## Key Collision

**Threat:** `ctrl+/` key conflicts with Claude Code binding or terminal multiplexer.

**Mitigations:**
- Collision check performed: not in app.rs handle_key, ui.rs help, or README (see RESEARCH.md)
- Documented in README and help overlay
- Note in README (or future docs) if users report conflicts

**Verification:** Code review of collision check; smoke testing in common terminals.

## Remote Session State

**Threat:** Remote session focus is not synced with local focus or crashes on attach.

**Mitigations:**
- Remote sessions read focus from daemon's SessionInfo.shell_open field
- attach_selected_remote() checks remote shell state before setting focus
- Fallback to Claude if remote session state is unavailable

**Verification:** Tests mock remote session attach with shell_open=true/false; verify focus is set correctly.

## Session Identity Across Switches

**Threat:** Focus is restored for wrong session (e.g., after session reorder or new session added).

**Mitigations:**
- Focus is keyed by SelId (Repository, Checkout, Standalone, Remote), which is stable across session reordering
- No persistent map of focus; focus is re-derived from session shell state on each activation
- Worst case: focus defaults to Claude (safe fallback)

**Verification:** Tests confirm focus is not persisted to wrong session after reordering.
</threat_model>
