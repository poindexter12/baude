<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User/path → filesystem/Git | An untrusted path or symlink is canonicalized and mapped to authoritative Git topology. |
| Git stdout → typed snapshot | Repository-controlled paths and refs cross from Git byte output into baude state. |
| Persisted allocation → `git worktree add` | A proposed managed path/ref may cause filesystem and Git mutation. |

## STRIDE Threat Register

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|-----------|----------|----------|-----------|-------------|-----------------|
| T-05-01 | Spoofing | High | `discover_repository` | mitigate/block | Canonicalize existing input, verify common-dir plus main-first inventory membership, preserve bytes, and block malformed or mismatched topology; covered by `admission_identity`. |
| T-05-02 | Tampering / Elevation | High | Git command boundary and default refs | mitigate/block | Use `Command` argv only, option terminators where supported, exact symbolic-ref prefixes, and verified commit targets; no shell interpolation or branch guessing. |
| T-05-03 | Tampering | High | `ensure_default_worktree` | mitigate/block | Reuse only inventory records, reject unregistered collisions, and rediscover common-dir/path/full branch ref after mutation before returning success. |
| T-05-04 | Denial of Service | Medium | Worktree porcelain parser | mitigate | Reject malformed/incomplete records with bounded fixture inputs; never panic or retain a partial snapshot. |
| T-05-SC | Tampering | Low | Cargo supply chain | accept | No package install or manifest/lockfile change is permitted in this plan; standard library and existing crates only. |
</threat_model>
