<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Launch dir → Workspace resolution | Untrusted launch dir canonicalized at startup; workspace derivation applies only for git repositories and sanitizes folder names |
| Repository root → State file path | Derived workspace names passed through sanitize() before use in state file paths |
| Folder-workspaces.json read/write | File in config dir (same permissions as breadcrumbs); advisory lock prevents concurrent corruption |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-01 | Tampering | find_binding ancestor walk | medium | mitigate | Walk is read-only (no writes in the walk itself); only recorded bindings are consulted; walk stops at home to prevent escape |
| T-13-02 | Spoofing | Derived workspace name injection | medium | mitigate | Workspace name sanitized via existing sanitize() function before use in state file paths; serde handles serialization, never string concat |
| T-13-03 | Elevation | Folder binding overwrite | low | mitigate | Binding is advisory metadata; explicit env vars and config always override bindings; lock guards state file writes |
| T-13-04 | Denial | Symlink traversal in walk | low | mitigate | Launch dir canonicalized at startup; walk uses exact BTreeMap key lookup (no glob/wildcard); no symlink-following in the walk itself |
| T-13-05 | Information | Config exposure via title | low | accept | TUI title shows workspace name (already visible in config); no secrets or sensitive data in display |
| T-13-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new external dependencies; phase uses only existing Rust ecosystem (tokio, serde, git2-rs already in Cargo.lock) |

</threat_model>
