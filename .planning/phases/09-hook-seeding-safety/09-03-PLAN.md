string-in/string-out contract.

<feature>
  <name>POSIX-quoted hook command with both-form recognizer</name>
  <files>baude-core/src/hook.rs (source + tests in the same file's tests mod)</files>
  <behavior>
    Producer: `quote_posix_single("/a b/baude")` returns `'/a b/baude'` (wrapped in single
    quotes); an embedded single quote in the input is replaced by the 4-char sequence
    quote, backslash, quote, quote (`'\''`) — one rule neutralizes space, `$`, `;`, and
    backtick (D-05). `baude_hook_command()`'s `Ok(current_exe)` arm returns
    `quote_posix_single(path) + " hook"`; the test override (:90) and the
    `FALLBACK_HOOK_COMMAND` arm are byte-for-byte unchanged (D-08; RESEARCH: overrides
    stay verbatim).

    Recognizer (D-07): after the unchanged `strip_suffix(" hook")`, two arms —
    if the remainder starts AND ends with a single quote, unquote it (strip outer quotes,
    invert the escape) and accept ONLY if `quote_posix_single(unquoted) == remainder`
    (strict round-trip — rejects malformed/user look-alike quotings, #78 class); otherwise
    treat the remainder as the legacy raw path. Either way the existing
    `is_absolute()` + file-stem `baude`/`bauded` check applies to the EXTRACTED path —
    unquote BEFORE `Path::new` (Pitfall 1: a quoted string is never `is_absolute()`).

    Cases (input → expected):
    - `'/opt/spa ced/baude' hook` → recognized (space)
    - `'/opt/a$b;c/bauded' hook` → recognized (`$`, `;`; stem bauded)
    - quoted path containing a backtick directory → recognized
    - quoted path containing an embedded `'` (escaped via the producer) → recognized
    - `/opt/baude hook` (legacy unquoted) → recognized
    - `baude hook` (bare fallback) → NOT recognized (never pruned, D-08)
    - `'/opt/vim' hook` → NOT recognized (stem)
    - `'relative/baude' hook` → NOT recognized (not absolute after unquote)
    - `''/opt/baude'' hook`, `'/opt/ba'ude' hook` (raw un-escaped inner quote),
      `'/opt/baude hook` (unterminated) → NOT recognized (round-trip fails)
    - Idempotency/convergence over merge_hook_settings: a file holding a seeded group for
      OLD quoted path `'/old/baude' hook`, re-seeded with `'/new/baude' hook` → exactly one
      group per event, command == the new quoted form (stale quoted installs are pruned —
      criterion 3, no per-path accumulation); merge(merge(x)) == merge(x); a legacy
      unquoted-seeded file re-seeded with a quoted command also converges to one group
      (D-06, D-07, Pitfall 2).
    - Purity: settings built by merge with a quoted command satisfy is_pure_seed_settings
      (freshly seeded worktrees keep their removal exemption); settings whose group holds a
      malformed look-alike quoting do NOT (#78 stays closed).
    - E2E (unix): a stub `#!/bin/sh` executable named `baude` inside a hostile directory
      (space, `$`, `;`, backtick, embedded `'` in the DIRECTORY name — the stub file name
      must stay `baude` for the stem check, Pitfall 5) is seeded via
      `TestRedirect::with_hook_command(quote_posix_single(stub) + " hook")` +
      `seed_settings(&cwd)`; the command string read back from the written
      settings.local.json, executed via `std::process::Command::new("sh").arg("-c")` with a
      MARKER env var, runs exactly that stub (marker file written by the stub exists) — 
      invocation proof, not string-form assertion (D-11).
  </behavior>
  <implementation>
