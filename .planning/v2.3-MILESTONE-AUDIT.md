### 1. TUI/Daemon Parity (Phases 14–15)

**Verdict:** ✓ WIRED — Identical behavior on both sides

#### Repository Admission
- **File:** `baude-core/src/lifecycle.rs::ensure_repository` (line 1357)
- **Usage:** Called by `lifecycle::prepare_activation` (line 1803) during branch worktree activation

- **Digest-based identity:** Phase 14 added `SavedRepository.physical_key` field; `ensure_repository` computes it as SHA-256 digest of common_dir; both TUI and daemon initially set it to key.get().to_string() (counter key) at admission time, then it's overwritten by the digest when collision detection runs during activation
- **Evidence:** app.rs:2054, manager.rs:1071 (initial physical_key), lifecycle.rs:1490 (ensure_repository sets actual_physical_key from digest)

#### Idle-Child Policy

  ```
  if !was_archived && s.archived && !s.archived_by_user {
      if let Some(note) = s.apply_idle_child_policy(policy) { ... }
  }
  ```
- **Manual archive:** Both apply policy after durable save (app.rs:5232-5246 for Checkout, manager.rs:2407-2410)
- **Shared implementation:** `Session::apply_idle_child_policy` (session.rs:419) called by both; suspend/resume/stop logic identical
- **Evidence:** session.rs:419-443, app.rs:3914-3931, manager.rs:2365-2393

#### Polling Gates
- **Archived/exited rows:** Both skip metadata polling (mtime check never runs) but still call auto_archive_tick:
  - app.rs:3917–3920: `if s.archived || s.claude.is_exited() { changed |= s.auto_archive_tick(...); continue; }`
  - manager.rs:2373–2376: identical
- **Mtime gating:** Implemented in baude-core `ClaudeMeta::poll_session_file` (meta.rs:253-306); called by both via `backend::active().poll_meta()`; checks `last_session_mtime`, skips read if unchanged (low-cost stat call)
- **Evidence:** meta.rs:253-264, app.rs:3916-3920, manager.rs:2371-2376

**Integration verdict:** Both TUI and daemon enforce the same policy, apply it at the same lifecycle points, and gate polling identically. ✓ WIRED

### 2. Workspace Derivation ↔ Worktree Identity (Phases 13–14)

**Verdict:** ✓ WIRED — Derivation and digest-keyed identity compose correctly

#### Workspace Derivation (Phase 13)
- **Function:** `baude_core::workspace::start_workspace` (called by both TUI and daemon at startup)
- **Derivation chain:** `BAUDE_WORKSPACE` env → folder binding → git toplevel folder name (sanitized) → config `workspace` → `BAUDE_BACKEND` → config `backend` → fallback "claude"
- **Binding recording:** `folder_workspace.rs` stores `{folder_root: workspace_name}` entries in `~/.config/baude/folder-workspaces.json`
- **Legacy support:** Counter-based directories (`repository-1`, `repository-2`) still resolve under a derived workspace; phase 14 Scanner does not migrate them, treating them as "unreadable" per design

#### Digest-Keyed Identity (Phase 14)
- **Directory path:** `~/.local/share/baude/worktrees/{workspace}/repository-{digest}` (or `-{digest}-{n}` if collision)
- **Digest computation:** SHA-256 of canonical `.git` common dir (unix.rs:1390 via `compute_repository_digest`)
- **Collision handling:** `check_collision` (lifecycle.rs:1497) detects when multiple repos map to the same digest-keyed path; allocates suffix `repository-{digest}-2`, `-3`, etc.; updates collision report with allocated path (line 1427)
- **Marker file:** Written to claimed directory to prove ownership after collision check (marker.rs); re-read on next scan to detect foreign markers

#### Composition Evidence
1. **Fresh repo launch from derived workspace:** User runs `baude` in `/home/user/my-project/src`; `start_workspace` derives workspace = `my-project` from repo root; `admit_repository` adds SavedRepository with physical_key = counter (temporary); when user activates a branch, `prepare_activation` calls `ensure_repository`, which recomputes physical_key as digest and detects collisions → stable identity
2. **Legacy counter dirs still work:** Old state files reference `repository-1` etc. under derived workspace; `load_named_at` (persist.rs, scanner) does NOT migrate them (locked decision: read-only scan, no write/migration); they appear in status as "unreadable" but don't block new repos
3. **Collision detection works post-state-reset:** If user deletes state file and re-admits same two repos, `ensure_repository` computes same digests, detects collision, allocates suffixes — stable identity restored from disk markers alone

**Integration verdict:** Phase 13 derivation establishes the workspace; phase 14 digest-based identity is computed within that workspace and persists stably. No interaction breaks. ✓ WIRED

### 3. Phase 15 (Idle-Child Policy) ↔ Phase 16 (Pane Focus)

**Verdict:** ✓ WIRED — Pane focus restoration respects suspended children; input always wakes before delivery

#### Pane Focus Restoration (Phase 16)
- **Storage:** `Session::pane_focus_shell: bool` (session.rs:99) — **in-memory only** (locked decision 16-CONTEXT.md D5)
- **Recording:** `remember_pane_focus()` (app.rs:4201-4210) sets `pane_focus_shell` when focus changes (before leaving a session)
- **Restoration:** `restore_pane_focus()` (app.rs:4216-4224) checks stored preference and current shell state, sets `Focus::Shell` or `Focus::Claude`

#### Interaction with Suspended Children
1. **Navigation:** `cycle_session` (app.rs:5427) changes selected session and calls `restore_pane_focus()`; child may be suspended at this point
   - restore_pane_focus checks `pane_focus_shell && shell_open && shell.is_some()` but NOT `child_suspended`
   - This is **safe** because the child is not accessed yet — only focus state is set
   
2. **Input delivery:** When user types:
   - `handle_key` → `forward_key` → line 4283: **`wake_selected_if_suspended()` called BEFORE write_input**
   - `handle_paste` → line 4357: **`wake_selected_if_suspended()` called BEFORE write_input**
   
3. **Resume on attach/activation:** `reopen_checkout` (app.rs:2577) calls `restore_pane_focus()` (line 2691) after runtime is re-attached; no input yet, so no race
   - Restoration only sets Focus; input will wake the child before delivery

4. **Restore after unarchive:** `apply_idle_child_policy` (session.rs:436-439) resumes child when transitioning from archived ← suspended; no pane-focus call at this point (resume happens in `apply_idle_child_policy` itself), so Focus is already set and child is awake

**Failure mode check:** Could a pane-focus restoration happen while a child is suspended but before input wakes it?
- Focus state change: safe (no child access)
- Any child operation: wake called first (forward_key:4283, handle_paste:4357)
- Child death (stop policy): Pty::kill() (session.rs:410) sets child_suspended = false; no pane focus restoration at this point

**Integration verdict:** Pane focus can be restored to shell of a suspended session, but all input paths wake the child first. ✓ WIRED

## End-to-End Flow Traces

### Flow A: Fresh Workspace Launch → Session Restore → Relaunch from Subfolder

**Trace:**
1. **Launch:** User runs `baude /home/user/my-project/src`
   - `start_workspace()` derived workspace = "my-project" from git root, records binding
   - `admit_repository()` creates SavedRepository with counter-based physical_key (temporary)
   - state file saved with workspace "my-project"

2. **Open session:** `Enter` on repository → opens session in `/home/user/my-project`

3. **Quit:** User presses `q` → `App::tick()` saves durable state with session Active/Launching

4. **Relaunch from subfolder:** User runs `baude /home/user/my-project/src/tests`
   - `start_workspace()` walks up, finds binding for `/home/user/my-project` → workspace = "my-project"
   - `load_state()` reads state file from `~/.local/share/baude/my-project/*.json` — same file
   - `restore_sessions()` recreates session with same checkout_key, same repository_key
   - Session appears in TUI, auto-resumes

**Result:** ✓ PASS — User lands in same workspace, session is restored

### Flow B: Two Repositories, Collision Detection, Distinct Directories

**Trace:**
1. **Repo A:** User clones into `/home/user/repo-a` (git common dir `/home/user/repo-a/.git`)
   - `admit_repository()` creates SavedRepository for common_dir, physical_key = "1"
   - Directory: `~/.local/share/baude/claude/repository-1`

2. **Repo B:** User activates a branch in `/tmp/repo-b` (git common dir `/tmp/repo-b/.git`, different common dir)
   - `prepare_activation()` calls `ensure_repository()` (lifecycle.rs:1803)
   - `ensure_repository()` computes digest for `/tmp/repo-b/.git` (different from repo-a)
   - `check_collision()` checks target dir `repository-{digest-b}` — does not exist
   - Directory: `~/.local/share/baude/claude/repository-{digest-b}`
   - SavedRepository.physical_key = digest-b (computed, not counter)

3. **Same digest collision (rare):** If repo C has same digest as repo B:
   - `ensure_repository()` detects collision (marker file from repo B exists)
   - `allocate_suffixed_repository_path()` allocates `repository-{digest-b}-2`
   - SavedRepository.physical_key = "digest-b-2"

**Result:** ✓ PASS — Each repository has distinct directory; collision handled with suffix

### Flow C: Auto-Archive, Suspend, Return, Type, Resume

**Trace:**
1. **Auto-archive timeout:** Session idle 30+ minutes
   - `tick()` → `auto_archive_tick()` sets archived = true (auto, not user)
   - `apply_idle_child_policy(Suspend)` calls `suspend_idle_child()`
   - SIGSTOP sent to agent (and shell if open); child_suspended = true

2. **User returns:** Clicks on archived session or types `alt+right` to cycle
   - `cycle_session()` selects session, calls `restore_pane_focus()`
   - Session focus is set; child still suspended (child_suspended = true)

3. **User types:** `handle_key()` → `forward_key()` 
   - Line 4283: `wake_selected_if_suspended()` called
   - `session.resume_idle_child()` sends SIGCONT to agent
   - child_suspended = false
   - Input forwarded to running child

4. **Unarchive on input:** `forward_key()` line 4306-4307 calls `unarchive_on_input()`
   - Sets archived = false, unarchived_at_ms = now
   - Saves state

**Result:** ✓ PASS — Child suspended, user returns, types, child resumes, input delivered
