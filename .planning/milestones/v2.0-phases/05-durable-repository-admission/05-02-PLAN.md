<interfaces>
Existing legacy shape that must remain strictly decodable with all fields preserved:
- `State { sessions: Vec&lt;SavedSession&gt; }`
- `SavedSession { name, cwd, repo_root, branch, is_worktree, shell_open, archived, archived_by_user }`
- `load_for_workspace(base, Workspace)` currently selects workspace-primary then the default workspace's unsuffixed fallback.
- `Workspace::state_file(base)` and `Workspace::legacy_state_file(base)` own workspace isolation and filename precedence.

New contracts:
- `RepositoryKey(u64)` and `CheckoutKey(u64)` are opaque, monotonic, persisted, path-independent, and meaningful only inside one workspace file.
- `PersistedPath(Vec&lt;u8&gt;)` is the durable representation for every persisted repository/checkout path observation on supported Unix targets: copy pathname bytes from discovery `PathBuf`/`OsStr` with `std::os::unix::ffi::OsStrExt::as_bytes`, serialize those bytes losslessly as a JSON byte array, and reconstruct a `PathBuf` with `std::os::unix::ffi::OsStringExt::from_vec`. It must never pass through `String`, `to_string_lossy`, or UTF-8 validation. Keep this adapter behind `cfg(unix)`; the Windows encoding/adapter remains deferred exactly as resolved in research.
- `CheckoutRole::{Main, PrimaryDefault, ManagedBranch}`; only one primary-default child per repository.
- `RepositoryHealth` / `CheckoutHealth` retain typed unavailable causes.
- `RepositoryState` owns allocation counters plus repository and checkout records and validates key uniqueness, foreign keys, roles, and monotonic ordering.
- `StateFile { schema_version, state }`, `LoadOutcome::{Missing, Legacy, Current}`, and typed `LoadError` distinguish absence, migration input, valid current state, malformed data, unsupported versions, and I/O failures.
- Production APIs retain workspace filename ownership; `_at`/state-root variants or an injected path resolver provide test isolation without process-global environment mutation.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| State-file bytes → durable aggregate | User-editable, legacy, truncated, or corrupt JSON becomes trusted repository intent only after strict decoding and validation. |
| Legacy session paths → repository ownership | Stale path facts may not prove current Git membership or baude ownership. |
| In-memory aggregate → state destination | A crash or filesystem error during replacement must not destroy the prior valid file. |
| Workspace selection → filename | Claude Code, OpenCode, local, and daemon state must remain isolated. |

## STRIDE Threat Register

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|-----------|----------|----------|-----------|-------------|-----------------|
| T-05-05 | Tampering / Repudiation | High | `load_for_workspace` | mitigate/block | Strict result-valued decoding, explicit schema/version checks, aggregate validation, source path in error, and no auto-default on malformed data. |
| T-05-06 | Tampering | High | atomic save | mitigate/block | Serialize first; unique sibling `create_new`; write/flush/sync/close/rename; failure tests assert exact old bytes and owned-temp-only cleanup. |
| T-05-07 | Spoofing | High | legacy migration ownership | mitigate/block | Migrate through reconciled Git identity, retain unresolved records unavailable, and never infer managed ownership from `is_worktree`. |
| T-05-08 | Information Disclosure / Tampering | High | workspace file selection | mitigate/block | Preserve `Workspace::state_file`/single fallback precedence; isolated-root tests prove no cross-workspace or local/daemon merging. |
| T-05-SC | Tampering | Low | Cargo supply chain | accept | No package installation or Cargo manifest/lock change; use Rust std fs plus existing serde stack. |
</threat_model>
