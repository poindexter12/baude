<objective>
HREG-03 tracer: replace the swallow-and-coerce read in `seed_settings` with a guarded
read that refuses to overwrite an unreadable/unparseable/non-object
`.claude/settings.local.json`, and wire the resulting structured warning end to end —
`hook.rs` → `Backend::prepare_cwd` → the TUI add-session spawn path — so the operator
sees a warning naming the file (D-01, D-02, D-04, D-10 unit half).

Purpose: this is the architectural slice of Phase 9. The warning seam (core returns
values, binaries present) crosses the crate boundary and forces the trait-signature
ripple; proving it on one call site first means the three remaining call sites
(09-04) are mechanical expansion, not architecture.

Output: `SeedWarning`/`SeedWarningReason` in baude-core, guarded `seed_settings`,
`Backend::prepare_cwd -> Vec<SeedWarning>`, TUI surface at the add-session path,
unit tests for every guard disposition.

## Decision Map (from 09-CONTEXT.md, cited as D-NN across Phase 9 plans)

- D-01: warn-and-leave-untouched triggers on read failure, parse failure, OR non-object
  root; a missing file is a normal fresh seed.
- D-02: seed functions return a structured warning value; callers surface it (TUI session
  UI, bauded warn-level logging); baude-core does no printing; the warning names the file.
- D-03: the same guard covers `.mcp.json` with an identical warning shape (plan 09-04).
- D-04: a write failure after a successful merge never aborts the spawn but fires the same
  warning path naming the file.
- D-05: POSIX single-quoting of the executable path, embedded `'` escaped, yielding
  `'<path>' hook` (plan 09-03).
- D-06: quote always, not conditionally (plan 09-03).
- D-07: `is_seeded_hook_command` accepts both the quoted and legacy unquoted forms (09-03).
- D-08: the bare `baude hook` fallback stays unquoted and is never pruned (09-03).
- D-09: `.mcp.json` `permission-mcp` command is quoted only if it goes through a shell —
  research answered NO (direct spawn), so it stays unquoted (plan 09-04).
- D-10: malformed-settings coverage = unit tests on the guard PLUS an app-level spawn test
  proving byte-identical file + surfaced warning (unit half here; app half in 09-04).
- D-11: spaced-path coverage is end to end through a real `sh -c` stub execution (09-03).
- D-12: the two v2.1.3 inspection-only lock behaviors become automated tests (plan 09-02).
- D-13: lock tests live beside the persist lock module and in bauded manager tests; hook
  tests in hook.rs units plus app-level integration (09-02, 09-04).
