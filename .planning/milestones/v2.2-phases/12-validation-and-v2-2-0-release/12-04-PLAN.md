<objective>
Get the phase chain onto `origin/main`'s shoulders and in front of CI for the
first time. Phases 8, 9, 10, and 11 are a single linear chain — each branch tip
is the next phase's planning commit — so the branch at HEAD contains all of them
and one pull request carries the lot. None of those branches has ever been
pushed, and the last `ci.yml` run was on the milestone planning branch, so
SHIP-01's "existing supported-platform CI checks pass" has literally no evidence
until this plan creates it.

GitHub Actions run), **D-08** (merge train: phase branches to main via the
existing PR flow), **D-10** (the existing release workflow outputs are reused
as-is and verified, not reworked), **D-11** (phase 8's stale verification is
surfaced as an explicit pre-release checklist item, not silently absorbed).

Purpose: SHIP-01's CI half, and the staged, reviewable state SHIP-04's human gate
acts on.
Output: a pushed branch, an open PR with three green required contexts, and
`12-RELEASE-CHECKLIST.md`.
</objective>

  <action>
    Per **D-08**, the merge train is one pull request, not four. Do not hardcode a branch name: resolve the current branch with `git rev-parse --abbrev-ref HEAD` and work with that. It descends from the phase-11 tip and therefore contains phases 8 through 11.

    1. `git fetch origin`. Then assert the lineage before touching anything, so a surprise is caught now rather than in the PR diff: for each of the phase-8, phase-9, phase-10, and phase-11 branch tips that exist locally, confirm with `git merge-base --is-ancestor <tip> HEAD` that HEAD contains it. Record each result. If any is not an ancestor, stop and report — the one-PR assumption no longer holds and the plan needs revisiting.

    2. Rebase onto `origin/main` to pick up the one commit HEAD is behind. Project git discipline: never base on a stale local default; branch and rebase from `origin/<default>`. Resolve conflicts if any appear — research expects the only divergent commit to be a `.planning/` docs commit.

    3. Re-run the full CI-parity bracket from plan 12-01 Task 2 after the rebase. A rebase produces a tree nobody has tested. This is cheap insurance against burning a CI cycle on a gate that already exists locally.

    4. Push the branch with upstream tracking. Do not force-push; `allow_force_pushes` is disabled on `main` and nothing here should need it on the phase branch either.
  </action>
