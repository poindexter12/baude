  <action>
    Merge the phase PR using the method the maintainer chose in Task 1. Then, per **D-09**, apply the hold label **before doing anything else at all** — not after updating the checklist, not after writing a summary, not after any other step.

    The reason is mechanical. `release-please.yml` fires on the push to `main`, opens or updates the release PR, labels it `release:minor`, and disables auto-merge on that tier. That disables one shortcut but not the live one: `release-automerge.yml` runs on a `*/30` cron and merges any open `release:minor` PR that is not labelled `release:hold`, once the two-hour soak has elapsed and required checks are green. The gate is opt-in. A two-hour window is comfortable, not free.

    So the sequence is: merge, then immediately look up the open PR carrying the `release:minor` label and add `release:hold` to it. release-please typically opens that PR within about a minute of the push; if the lookup returns nothing yet, re-run the lookup until it returns a number. Do not insert other work while waiting.

    Once the label is on, confirm two things and record them in `12-RELEASE-CHECKLIST.md` under a `## Release PR` heading: that `release:hold` is actually present on the PR, and that the PR proposes 2.2.0 rather than 2.1.6 or nothing at all. A proposal of 2.1.6, or no release PR appearing within a few minutes, is the warning sign that the merge did not produce the conventional-commit history release-please needed — investigate before going further.

    Also record the merge commit sha and the release PR number and URL.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| maintainer decision → automated pipeline | Publish authorization is the only place a human decision enters an otherwise fully automated release. |
| `release-automerge.yml` cron → the release PR | A scheduled job with merge authority operates on the release PR every 30 minutes; the only thing standing between it and a publish is an opt-in label. |
| release assets → downloaders | Published tarballs and a container image are consumed by users who did not build them. |
