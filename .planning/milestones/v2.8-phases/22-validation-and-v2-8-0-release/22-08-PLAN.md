What plan 22-07 built, which these tests rest on:
- Removing a `PrimaryDefault` row writes its suppression entry with a `primary` flag. `suppression::removed_primary(root, common_dir)` returns the flagged entry's path for that repository.
- `admit_repository` lifts the entry of the folder it was given, then derives no primary while a flagged entry of the repository remains.
- So the fact ends in two ways only: `lift` of that exact path, which launching inside the folder, `n` naming it and `c` into it all do; or `drop_children` when the repository row is removed.
- A folder the removal deleted cannot be named by any route while it is gone. "Launching inside the folder" then means the folder exists again: a worktree put back at that path. The other way back is through the repository row.

- Every test here is expected to pass on the tree plan 22-07 left. One that fails is a finding: stop and return with its output. Do not change product code, and do not weaken the assertion.
