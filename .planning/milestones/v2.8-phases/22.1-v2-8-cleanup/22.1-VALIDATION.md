## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `cargo test` with in-crate `mod tests`, `#[tokio::test]` for bauded; `node --test` on Node 26 for `bauded/web/tests`; the new `scripts/assert-no-test-leftovers.sh` observing every suite run from outside the test process |
| **Config file** | none; workspace `Cargo.toml`; `scripts/check-web-suites.sh` |
| **Quick run command** | the task's own `<automated>` command; Rust runs go through `bash scripts/assert-no-test-leftovers.sh run "$T" -- cargo test -p <crate> ... -- --test-threads=1` with `T` from `mktemp -d "${TMPDIR:-/tmp}/..."`, outside every git work tree |
| **Full suite command** | `scripts/gate.sh`, then `scripts/gate.sh --linux`, both run by the orchestrator before the push, never inside a plan |
| **Estimated runtime** | not measured at planning time; per-crate runs take minutes, plan 22.1-06 Task 3 runs the whole workspace once |

Every exit code is read directly. No test, gate or script command is piped into `tail` or `grep` to be judged by `$?`. Each `<automated>` command echoes its exit codes on one line and then tests them. Evidence files go under git-ignored `target/gsd-22.1/`.

---

## Sampling Rate

- **After every task commit:** the task's `<automated>` command. The last task of each code plan adds `cargo fmt --check`, `cargo clippy ... --all-targets -- -D warnings` for the crates it touched, and `scripts/check-commit-message.sh --range <base>..HEAD` against the base sha recorded in Step 0.
- **TDD gates:** every `tdd="true"` task keeps its RED log under `target/gsd-22.1/` from a run that failed on the assertion the task names, read before the GREEN edit, and commits the red test alone first. Tasks that pin behaviour an earlier plan built use a bite check instead: a temporary change named in the task makes the test fail into a kept log, then the file is restored and never committed.
- **Leftover sampling:** from plan 22.1-03 on, every Rust test run in a verify goes through `assert-no-test-leftovers.sh run`, so each plan proves its own tests leave no orphaned runtime, no live runtime and no fixture entry. From plan 22.1-06 on, the gate and CI do the same for the whole workspace.
- **Wave order:** execution is serial on one tree. Waves only order plans that share files: PWA and the leftover script first, then the guards, then the three crates' fixture roots, then the gate wiring, then suppression, then the WR-06 chain of core split, daemon exclusion, unlocked removal and window evidence.
- **Before `/gsd-verify-work`:** `scripts/gate.sh` and `scripts/gate.sh --linux` both exit 0 on the pushed commit. The Linux gate is required: plan 22.1-10 moves PTY kills to a blocking-pool thread and plans 22.1-02 to 22.1-06 read the process table per platform.
- **Max feedback latency:** not measured.
