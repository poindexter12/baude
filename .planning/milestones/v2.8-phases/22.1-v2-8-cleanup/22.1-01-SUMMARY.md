## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The RED title test redeclared two suite helpers**
- **Found during:** Task 1 GREEN
- **Issue:** The new test declared its own `repositoryReport(deleted, overrides)` and `standaloneReport`, but removal.test.js already declares both further down. Function declarations hoist and the later one wins, so the repository cases got an array as their overrides and the test saw 2 deleted folders where it expected 1. The RED run was still valid: it failed on the first assertion, the checkout title, before reaching the repository cases.
- **Fix:** Dropped the duplicate declarations. The test now calls the existing factories through a local `repository(deleted, overrides)` wrapper. No assertion was changed or weakened.
- **Files modified:** bauded/web/tests/removal.test.js
- **Commit:** 561985e, with the GREEN change, as the commit body says

**2. [Rule 1 - Consistency] web.rs old-name guard moved with the cache bump**
- **Found during:** Task 2
- **Issue:** The plan named the new-name assertion and its message. The same test also asserts `!worker.contains("baude-v6")` with the message "the old cache name is still served". Left as is, it would no longer check the generation just retired.
- **Fix:** Changed it to `baude-v7`. `baude-v8` does not contain that string.
- **Files modified:** bauded/src/web.rs
- **Commit:** fd75023

**3. [Style] app.js reads `getRows()` once**
- The plan's wording calls `removalController.getRows()` inline in the `keyless` argument. The edit reads it once into a block-scoped `rowsBody` and passes that to both `renderRowsList` and `unclaimedSessions`. It is the same object, so the behaviour is the same. The card callback still returns `rowHtml(s)` for a known session and null otherwise. The branch without a controller is unchanged.
