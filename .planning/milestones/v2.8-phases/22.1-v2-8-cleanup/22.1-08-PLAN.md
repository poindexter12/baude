Shapes, as recommended by research; names may differ, behaviour may not:
- `pub struct PreparedRemoval` holding the `RemovalSet` and the planned clearings, fields private.
- `pub struct StageEffects` holding the killed runtimes and the disk results, fields private.
- `pub fn prepare(state: &RepositoryState, target: RemovalTarget, runtimes: &[RowRuntime]) -> Result<PreparedRemoval, RemovalError>`: `select_rows`, `planned_clearings`, `preflight`, then a candidate clone with the set's rows removed and `validate_for_save`, discarded, so a validation refusal still comes before any irreversible effect.
- `pub fn stop_and_delete(prepared: &PreparedRemoval, runtimes: &mut [RowRuntime]) -> Result<StageEffects, RemovalError>`: `kill_stage` then `disk_stage`.
- `pub fn commit(state: &mut RepositoryState, prepared: PreparedRemoval, effects: StageEffects, runtimes: &mut Vec<RowRuntime>, save: impl FnOnce(&StateFile) -> Result<(), SaveError>) -> Result<RemovalReport, RemovalError>`: re-select the prepared target against `*state` and compare row keys only, since a deleted directory now reads as already removed; then clone `*state`, remove the set's rows, `validate_for_save`, `persist_stage` once, `clear_stage` with the rows that clone dropped, `report_from_set`. `*state` is untouched on every error.
- `RemovalError::SelectionChanged { target, expected: Vec<RowKey>, found: Vec<RowKey> }` with a `Display` naming both lists. It follows an irreversible effect, so under correct exclusion it is unreachable; the daemon maps it to 500.
- `pub fn capture() -> Redirects` returns the current thread's redirects; `TestRedirect::install(redirects: Redirects) -> TestRedirect` swaps them in on the calling thread and restores on drop. `Redirects` must be `Send`; add a compile-time assertion.
