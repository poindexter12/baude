Interface the later plans rely on, fixed here:

- `assert-no-test-leftovers.sh run <dir> -- <command> [args...]`: creates `<dir>` if missing; refuses with exit 2 when `<dir>` resolves inside a git work tree, or already holds a `baude-*` or `bauded-*` entry; runs the command with `TMPDIR` set to `<dir>` exactly as given, never its realpath; samples processes while it runs; then runs the end check. Prints exactly one line `assert-no-test-leftovers: command=<rc> orphans=<n> live=<n> dirs=<n>` on stdout, details on stderr. Exit 0 when all four are 0, exit 1 otherwise, exit 2 on usage or internal error.
- `assert-no-test-leftovers.sh check <dir>`: the end check alone, same summary line with `command=-`.
- `--self-test`: synthetic cases only, never a cargo run.
- Environment: `BAUDE_ASSERT_PYTHON` names the interpreter, default `python3`; `BAUDE_LEFTOVER_SAMPLE_SECS`, default 2; `BAUDE_LEFTOVER_PERSIST_SECS`, default 5.

Definitions:
- Fixture entry: a top-level name in `<dir>` beginning `baude-` or `bauded-`, file or directory.
- Process cwd: Linux reads `/proc/<pid>/cwd` and strips a trailing ` (deleted)`; macOS parses `lsof -nP -w -d cwd -Fpn` for all processes, ignoring its exit status when output parsed, and fails with exit 2 if `lsof` is missing. Compare `os.path.realpath` of both sides.
- Descendant: walk the parent chain from a snapshot of every pid and ppid, read from `/proc/<pid>/stat` on Linux, parsing after the last `)`, and from `ps -axo pid=,ppid=` on macOS, until it reaches the script's own Python pid or pid 1.
- Orphan: a process whose cwd is under `<dir>`, which is not a descendant, and whose pid and command were seen in two samples at least the persist window apart. A test that kills a leader and reaps the child it orphaned within the window is not flagged.
- Live: any process other than the script whose cwd is under `<dir>` at the end check.
- The script observes only: it never signals, kills or deletes anything outside its own self-test scratch.
