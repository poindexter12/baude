<objective>
Add the TUI activity overlay (ACT-04): a new `Modal::Activity` opened by `v`, rendering the recent tool sequence newest-at-bottom, mirroring the existing `i` Info overlay's `Clear`+`Paragraph`+`Block` structure and its local-vs-remote branch. Local sessions read `s.meta.activity()` directly; remote sessions read a bounded `RemoteInfo.activity` bundled into the `/sessions` poll (the field added to `SessionInfo` in plan 02), so the remote overlay needs no extra round-trip. Live refresh is free — the 50 ms draw loop re-renders the open modal every tick.

Purpose: This is the terminal-side surface of the feed — at-a-glance "what is this session doing right now" for the currently selected session, local or remote, matching how `i` already works.

Output: `RemoteInfo.activity` field, `Modal::Activity` variant + `v` dispatch + dismiss, the `draw_modal` render arm. NOTE: `baude/src/app.rs` has NO test seam today (`#[cfg(test)]` count = 0, `handle_*_key` are private, `App::new` needs a real launch_dir) — per 03-VALIDATION.md Wave-0 check, ACT-04 open/dismiss is human-verify UAT, NOT a unit test. Do NOT build a TUI test harness for this phase (consistent with Phase-2's human-verify UAT for TUI behavior).
</objective>
